Tout ce qu'il faut lancer, ouvrir et dire,dans l'ordre.

Cette page est ma liste d'actions pour la soutenance : seulement ce qu'il reste à faire le jour J. 01

Déjà en place, rien à refaire

Tout ceci est configuré une fois pour toutes. Le jour J, je ne touche à rien de cette liste.

MODÈLE

Poids publiés

Qwen3-1.7B-Base fusionné (SFT ckpt-550 + DPO ckpt-150) sur le dépôt Hugging Face privé SteGONZALEZ/qwen3-triage-chsa.

DONNÉES

Datasets publics

sft.jsonl et dpo.jsonl sur SteGONZALEZ/medical_triage_agent, découpage dans final_split.

RUNPOD

Deux templates prêts

triage-vllm (GPU, image vllm/vllm-openai:v0.31.0, port 8000) et triage-api (CPU, image GHCR de l'API). Le modèle se télécharge seul au démarrage.

CODE

CI / CD au vert

Chaque push lance Ruff et les tests, puis publie l'image de l'API sur GHCR avec le SHA du commit.

POSTE

.env et monitoring

Clé vLLM, mot de passe Grafana, INFERENCE_BACKEND=vllm et VLLM_METRICS_SCHEME=https déjà remplis ; dashboard Grafana provisionné automatiquement.

MESURES

Chiffres déjà relevés

Test gelé via vLLM le 13 octobre (L4) : 453/500, 500 décisions identiques, 0 invalide, P95 1,13 s. Pas besoin de le relancer en démo.

SÉCURITÉ Aucune clé à l'écran.

Ne pas ouvrir .env pendant la démo, ni la page Secrets de RunPod, ni les variables d'environnement d'un pod. Les cas présentés sont fictifs : RunPod n'est pas un hébergeur certifié HDS.

02

Le jour J, à faire dans l'ordre

Environ 30 minutes avant de commencer. Les commandes sont en PowerShell, depuis la racine du projet, dans une seule fenêtre gardée ouverte.

T-30 • Poste

Démarrer Docker et libérer les ports

Lancer Docker Desktop. Si un autre conteneur occupe le port 8000 : docker stop chess-agent-backend.

T-30 • GPU

Déployer le pod vLLM

RunPod › Pods › Deploy : GPU en Europe (L4 ou RTX 4000 Ada), Change Template › triage-vllm, Deploy. Vérifier avant de valider que l'image est vllm/vllm-openai:v0.31.0. Dans les logs du conteneur, attendre Application startup complete (environ 2 minutes une fois l'image téléchargée). Si les logs montrent TLS handshake timeout ou Nginx / Jupyter, mauvaise machine ou mauvais template : Terminate et redéployer.

T-20 • Id du pod

Récupérer l'identifiant

Sur la page du pod, l'identifiant est sous son nom (ex. n7voo3el6hv7x6). Le copier plutôt que le retaper (« l » et « 1 » se confondent). Il change à chaque déploiement.

T-20 • Contrôle

Vérifier que le modèle répond

Étapes 1 à 3 du bloc PowerShell ci-dessous. Attendu : "id":"triage-qwen3". Unauthorized = clé non chargée dans la fenêtre ; 502 = pas encore prêt.

T-15 • .env

Mettre l'id du pod dans .env

Hors écran, remplacer l'id sur deux lignes : VLLM_BASE_URL et VLLM_METRICS_TARGET.

T-15 • Service

Lancer l'API et le monitoring

Étapes 4 et 5. /health doit répondre ok et /version afficher qwen3-1.7b-base-sft162715-ckpt550-dpo-ckpt150.

T-10 • Grafana

Remplir les courbes

Étape 6 : la rafale des dix cas inédits (30 requêtes). Prometheus › Targets : API et vLLM « UP ». Les courbes apparaissent après une à deux minutes. Se connecter à Grafana maintenant, pour que le mot de passe n'apparaisse pas pendant la démo.

T-5 • Onglets

Ouvrir les onglets

Dans l'ordre de la section suivante. Zoom du navigateur à 125 %, notifications coupées, terminal en grande police.

04

Le déroulé, en dix minutes

0:00 • Contexte

Le besoin du CHSA

Onglet 1. Trier les patients en P1, P2, P3 avec une justification, sur du matériel modeste. Un petit modèle (Qwen3-1.7B) entraîné sur une carte de 6 Go.

1:30 • Méthode

Données, SFT, DPO

Onglet 2. 5 000 cas FR/EN nettoyés et anonymisés, SFT puis DPO, choix sur la validation, mesure unique sur un test gelé : 90,62 % de F1, 5,4 % de sous-triage. Puis l'onglet Base / Instruct : pourquoi la Base ne s'arrêtait pas, et la correction.

3:00 • Architecture

Du modèle au service

Onglet 3. Modèle fusionné et vérifié, servi par vLLM sur un GPU RunPod ; API FastAPI ; Docker ; CI/CD.

4:00 • Démo

Trois cas en direct

Onglet 4. AVC en anglais (P1), poussée de BPCO (P2), lombalgie (P3), en forme complète. Lire la priorité, l'explication, la recommandation et la latence renvoyées.

6:00 • Monitoring

Le service observé

Onglet 5. Les requêtes qui viennent d'arriver, la latence moyenne et p95, aucune erreur, API et vLLM disponibles. Aucune donnée patient dans les métriques. Puis le journal d'audit dans le terminal : docker compose exec api tail -n 3 /app/logs/audit.jsonl, une ligne par décision, avec le même request_id que la réponse et une empreinte à la place du texte.

7:00 • Limite

Le cas qui échoue

Onglet 4. La douleur thoracique en forme complète passe en P1 ; la même sans constantes repasse en P2 alors que l'explication écrit « suggests a heart attack ». Puis le purpura : priorité juste, mais l'explication invente « paludisme et tétanos ». Expliquer pourquoi (mots-clés, peu de constantes à l'entraînement) et ce qui est prévu.

8:30 • Conclusion

Second avis, pas décision

Le POC est faisable et industrialisable ; il ne doit pas trier seul. Proposition : second avis pour l'IOA, filet de sécurité par règles, évaluation sur cas réels.

Les questions probables

QuestionMa réponse courteOù le montrer
Pourquoi un si petit modèle ?Contrainte de la mission : entraînement sur 6 Go de VRAM et service peu coûteux. 1,7 milliard de paramètres en QLoRA tient sur ce matériel.SFT
Le score est-il fiable ?Test gelé de 500 cas jamais utilisé pour choisir, analyse de fuite, vérification après fusion (492/500 décisions identiques) et via vLLM (500/500).Résultats
À quoi sert le DPO s'il ne change pas le triage ?La priorité est la même dans les deux réponses et s'annule dans la loss : le DPO ne règle que le style des explications, et l'effet mesuré est faible.DPO réaligné
Pourquoi rate-t-il l'infarctus sans constantes ?Il a appris l'urgence à partir de mots alarmants et de constantes ; les infarctus sont rares dans le train (30 sur 4 000). Avec les constantes, la Base le classe P1.Causes
Que se passe-t-il si vLLM tombe ?L'API renvoie une erreur 503 explicite, la disponibilité passe au rouge dans Grafana ; aucune priorité n'est inventée.Architecture
Et les données de santé ?Données publiques anonymisées (Presidio) ; en production : hébergement HDS, AIPD, contrôle humain.Synthèse
Pourquoi d'abord l'instruct, puis la Base ?La mission impose la Base. J'ai d'abord pris la version post-entraînée, qui connaît le format de conversation. La Base ne terminait pas ses réponses : <|im_end|> jamais entraîné (norme 0,375), LoRA ne touche pas les lignes de jetons. Correction, même niveau (453/500), sous-triage 7,2 → 5,4 %.Base / Instruct
Peut-on auditer une décision ?Oui : chaque appel laisse une ligne avec identifiant, horodatage, versions du modèle et du prompt, priorité et latence. Le texte du patient n'y est pas, seulement son empreinte.Architecture
Est-il prêt pour la production ?Le POC atteint ses objectifs (sous-triage 5,4 %, rappel P1 93,4 %, P95 1,13 s via vLLM). Avant déploiement, les cibles sont plus exigeantes : rappel P1 95 %, aucun P1 en P3, sous-triage 5 %, écart FR/EN 5 points, AIPD et HDS. C'est la marge de progression de la phase 0 et 1 ; d'ici là, pas de données réelles.Go / no-go
Où est le questionnaire adaptatif ?Hors du POC : le modèle classe un cas déjà décrit. Le test des cas inédits montre qu'un cas complet donne de meilleures réponses, d'où le questionnaire en feuille de route.Résultats
Combien ça coûte ?Moins de 0,60 $ de l'heure pour le GPU de démonstration ; l'API tourne sur CPU.Cloud
